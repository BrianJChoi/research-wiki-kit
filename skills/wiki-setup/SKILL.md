# 위키 세팅 (연구 볼트용)

## 공용 경로

먼저 이 스킬 파일에서 상대 경로 `../../references/vault-layout.md`를 읽고, 대상 볼트의 `CLAUDE.md`와 함께 적용합니다. 아래 경로 예시는 공용 표의 역할을 뜻하며 사용자 규칙이 우선합니다.

나만의 연구 LLM Wiki 뼈대를 만듭니다. 구조는 공용 경로 표와 사용자 지시에 맞춥니다. 이미 확정한 구조는 다시 확인받지 않습니다.

## 1. 읽기

1. 볼트 맨 위의 `CLAUDE.md`를 읽습니다. 연구 주제, 분야, 쓰는 언어가 적혀 있으면 구조안에 반영합니다.
2. 이미 있는 폴더와 파일을 확인합니다. 있는 것은 새로 만들지 않습니다.
3. `CLAUDE.md`가 없거나 연구 주제가 비어 있으면 세 가지만 묻습니다. 연구 분야, 지금 연구 주제 한 줄, 주로 읽는 자료(논문, 보고서, 웹 글).

## 2. 구조안 제안

아래 기본안을 보여 주고, 항목마다 왜 필요한지 한 줄씩 붙입니다. 사용자 상황에 맞게 이름을 바꿔도 됩니다.

공용 경로 표의 원문·위키·논문 노트·토픽·연구·데일리·템플릿과 서지 파일의 역할을 설명합니다. 폴더 이름은 그 표에서 읽습니다.

사용자가 구조를 이미 지정했으면 바로 진행합니다. 미정인 이름이나 기존 구조 변경만 확인받습니다.

## 3. 만들기

승인받은 폴더와 `Wiki/INDEX.md`, `Wiki/log.md`를 만듭니다. 이미 있는 파일은 건드리지 않습니다.

## 4. CLAUDE.md에 운영 규칙 더하기

`CLAUDE.md` 끝에 아래 규칙을 더합니다. 이미 비슷한 규칙이 있으면 더하지 않고 알려 줍니다.

```markdown
## 위키 운영 규칙

1. 원문 폴더의 파일은 고치지 않습니다.
2. 위키 페이지를 만들거나 고치면 `Wiki/INDEX.md`를 갱신합니다.
3. 모든 위키 작업은 `Wiki/log.md`에 한 줄로 기록합니다.
4. 노트끼리는 `[[노트 이름]]`으로 잇습니다.
5. 모든 위키 페이지에 YAML 속성을 붙입니다.
6. 질문에 답할 때는 INDEX부터 봅니다. 원문은 마지막에 봅니다.
7. 새 페이지보다 기존 페이지 보강을 먼저 합니다.
8. 저자의 말, 내 해석, AI 요약을 구분해 씁니다.
9. 출처가 서로 다른 말을 하면 둘 다 인용합니다.
10. 논문은 `[[Literature/@인용키]]`로 인용하고, 가능하면 쪽을 적습니다.

## 하이라이트 색 규칙

- 초록: 핵심 주장
- 노랑: 방법·데이터
- 빨강: 반론·한계
```

## 5. 보고

만든 폴더와 파일, `CLAUDE.md`에 더한 부분을 알려 줍니다. 다음 단계로 템플릿 만들기와 첫 ingest를 제안합니다.

## 지킬 것

- 요청 범위 밖의 폴더 이동이나 기존 규칙 덮어쓰기는 하지 않습니다.
- 사용자가 말하지 않은 연구 정보를 지어내지 않습니다. 모르면 묻습니다.

## 템플릿도 만들기

논문·토픽·데일리 템플릿이 없으면 만듭니다. 논문은 `../paper-note/references/default-template.md`를 사용합니다. 토픽 템플릿은 YAML `title`, `created`, `tags: [topic]`과 본문의 질문·관련 논문·근거·내 생각을, 데일리는 `created`, `tags: [daily]`와 오늘 배운 것·연결한 노트·다음 행동을 포함합니다. 내 생각은 비워 둡니다. 사용자 템플릿이 있으면 보존하고 새로 만들지 않습니다. `references.bib`는 Better BibTeX의 자동 내보내기로 만드는 파일이므로 빈 파일을 만들거나 가짜 서지를 넣지 않습니다.
