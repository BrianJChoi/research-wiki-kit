# 논문 노트

## 공용 경로

먼저 이 스킬 파일에서 상대 경로 `../../references/vault-layout.md`를 읽고, 대상 볼트의 `CLAUDE.md`와 함께 적용합니다. 아래 경로 예시는 공용 표의 역할을 뜻하며 사용자 규칙이 우선합니다.

Zotero 논문 한 편을 골라, 내가 Zotero에서 남긴 하이라이트와 코멘트를 **내 논문 노트 템플릿**에 옮깁니다.

이 노트는 누구의 말인지 나눠 담습니다. 나중에 노트를 다시 볼 때 저자의 말, 내 말, AI의 말이 섞이지 않게 하기 위해서입니다.

| 부분 | 누구의 말 | 이 스킬이 하는 일 |
|---|---|---|
| 하이라이트 | 저자의 말 | Zotero에서 그대로 옮깁니다 |
| 내 코멘트 | 내가 읽으며 남긴 말 | Zotero에서 그대로 옮깁니다 |
| 요약의 AI 요약 | AI의 말 | 초록만 보고 2~3줄로 씁니다. AI가 쓴 것이라고 표시합니다 |
| 내 생각 | 나의 말 | **비워 둡니다.** 사용자가 직접 씁니다 |

## 지킬 것

- **Zotero에 없는 내용은 지어내지 않습니다.** 값이 없으면 속성 값을 비워 두고, 본문에는 "Zotero에 없음"이라고 적습니다.
- **Zotero에는 아무것도 쓰지 않습니다.** 읽기 도구만 씁니다. `zotero_update_item`, `zotero_create_annotation`, `zotero_manage_note`처럼 Zotero를 바꾸는 도구는 부르지 않습니다.
- **본문 전체는 읽지 않습니다.** 서지 정보, 초록, 주석, Zotero 노트만으로 만듭니다. 논문 한 편의 본문은 사용량을 크게 씁니다. 본문까지 읽고 싶으면 사용자가 따로 요청합니다.
- **있는 노트를 덮어쓰지 않습니다.** 7단계를 따릅니다.
- "내 생각"에는 AI가 아무것도 쓰지 않습니다.

## 0. 준비 확인

1. Zotero 앱이 켜져 있어야 합니다. Zotero MCP 도구 이름은 `zotero_search_items`처럼 보이거나 앞에 서버 이름이 붙어 `mcp__zotero__zotero_search_items`처럼 보일 수 있습니다. 도구가 없거나 응답이 없으면 Zotero가 켜져 있는지 사용자에게 확인합니다.
2. 볼트 맨 위의 `CLAUDE.md`가 있으면 읽습니다. 논문 노트 폴더, 템플릿 폴더, `하이라이트 색 규칙`이 적혀 있으면 그대로 따릅니다.

## 1. 논문 찾기

사용자가 준 단서에 따라 찾습니다.

| 단서 | 도구 |
|---|---|
| 인용 키 (`@Kim2024`, `Kim2024`) | `zotero_search_by_citation_key(citekey="Kim2024")` (앞의 `@`는 뺍니다) |
| 제목, 제목 일부, 저자와 연도 | `zotero_search_items(query="<단서>", qmode="titleCreatorYear", limit=5)`. 결과가 없으면 `qmode="everything"`으로 한 번 더 |
| "방금 넣은 논문", "최근 논문" | `zotero_get_recent(limit=5)` |

후보가 여러 개면 번호를 붙여 제목, 첫 저자, 연도를 보여 주고 사용자에게 고르게 합니다. 한 편만 맞으면 그 항목으로 진행합니다. 이후 단계는 이 항목의 키(`item_key`)를 씁니다.

## 2. 서지 정보 읽기

`zotero_get_item_metadata(item_key="<키>", include_abstract=True, format="json")`

| 노트 속성 | Zotero 값 | 규칙 |
|---|---|---|
| `title` | 제목 | 그대로 |
| `authors` | 저자 목록 | 목록으로 씁니다. 한글 이름은 성과 이름을 붙여 쓰고(`이한샘`), 그 밖의 이름은 `성, 이름`(`Smith, John`)으로 씁니다. 기관 저자는 이름 그대로 |
| `year` | 날짜 | 연도만 (예: `2024`). 없으면 비워 둠 |
| `citekey` | 인용 키 (`citationKey`) | 아래 참고 |
| `journal` | 학술지, 학회, 출판사 | 있는 것 하나. 없으면 비워 둠 |
| `doi` | DOI | 없으면 비워 둠 |
| `url` | URL | 없으면 비워 둠 |
| `zotero` | 항목 키 | `zotero://select/library/items/<항목 키>` |
| `tags` | Zotero 태그 | `literature`를 넣고 Zotero 태그를 더합니다. 태그 속 공백은 `-`로 바꿉니다 |
| `created` | 오늘 날짜 | `YYYY-MM-DD` |

**인용 키가 비어 있으면** `format="bibtex"`로 다시 읽어 `@article{인용키,` 부분을 확인합니다. 그래도 없으면 키를 만들어 내지 않습니다. 사용자에게 Zotero의 Better BibTeX를 확인해 달라고 하고, 지금 진행하길 원하면 파일 이름을 `@zotero-<항목 키>.md`로 하고 `citekey` 값은 비워 둡니다.

## 3. 하이라이트와 코멘트 읽기

1. `zotero_get_annotations(item_key="<키>", format="json")`. 항목 키를 꼭 넣습니다. 빼면 서재 전체의 주석이 나옵니다.
2. 주석마다 `type`, `text`(하이라이트한 문장), `comment`(내 코멘트), `color`, `color_category`, `page`(쪽 표시), `page_index`, `attachment_key`, `annotation_key`를 씁니다.
3. `page_index`가 없으면 링크의 page를 추측하지 말고 주석 링크에서 page를 생략합니다. 그룹 서재는 응답의 실제 Zotero URI를 쓰며 개인 서재 URI로 바꾸지 않습니다.
4. 결과가 비어 있으면 "Zotero에 하이라이트가 없습니다"라고 알립니다. 사용자가 다른 앱(태블릿 등)에서 PDF에 직접 표시했다고 하면 `use_pdf_extraction=True`로 한 번 더 읽습니다.
5. `zotero_get_notes(item_key="<키>")`로 이 논문에 달린 Zotero 노트를 읽습니다. 없으면 건너뜁니다.

## 4. 색 규칙 정하기

색 의미는 이 순서로 찾습니다.

1. 볼트 `CLAUDE.md`의 `하이라이트 색 규칙`
2. 논문 노트 템플릿 안에 적힌 색 규칙
3. 아래 표의 수업 기본 규칙

| 색 | Zotero 색 코드 | 이름 | 의미 (신호등 규칙) |
|---|---|---|---|
| 초록 | `#5fb236` | Green | 핵심 주장 |
| 노랑 | `#ffd400` | Yellow | 방법·데이터 |
| 빨강 | `#ff6666` | Red | 반론·한계 |
| 파랑 | `#2ea8e5` | Blue | 사용자 규칙 |
| 보라 | `#a28ae5` | Purple | 사용자 규칙 |
| 자홍 | `#e56eee` | Magenta | 사용자 규칙 |
| 주황 | `#f19837` | Orange | 사용자 규칙 |
| 회색 | `#aaaaaa` | Gray | 사용자 규칙 |

의미가 "사용자 규칙"인데 1, 2에도 적혀 있지 않으면 색 이름만 쓰고 의미는 비워 둡니다. 의미를 추측하지 않습니다. 노트를 다 만든 뒤 "색 규칙을 `CLAUDE.md`에 적어 두면 다음 노트부터 반영합니다"라고 알려 줍니다. 사용자가 원할 때만 `CLAUDE.md`에 적습니다.

## 5. 템플릿 고르기

1. 템플릿 폴더(`CLAUDE.md`에 적힌 곳, 없으면 `Templates/`)에서 이름에 `논문`, `문헌`, `literature`, `lit`, `paper`가 들어간 파일을 찾습니다. 대소문자는 가리지 않습니다.
2. 하나면 그 파일을 씁니다. 여러 개면 사용자에게 고르게 합니다.
3. 없으면 이 스킬의 `references/default-template.md`를 쓰고, 기본 템플릿을 썼다고 알립니다.

템플릿을 쓰는 규칙:

- 템플릿의 속성 이름과 순서, 제목, 고정 문구를 그대로 둡니다.
- `{{title}}`은 논문 제목, `{{date}}`는 오늘 날짜(`YYYY-MM-DD`), `{{time}}`은 지금 시각으로 바꿉니다.
- `<% ... %>` 같은 Templater 문법은 실행하지 않습니다. 뜻이 분명하면 같은 값으로 바꾸고, 아니면 비워 두고 알려 줍니다.
- 템플릿에 있는데 Zotero에 값이 없는 속성은 값을 비워 둡니다.
- 템플릿에 필요한 속성이나 아래 네 부분(요약, 하이라이트, 내 코멘트, 내 생각)이 없으면 끝에 더하고, 무엇을 더했는지 알려 줍니다.

## 6. 채우기

### 요약

1. Zotero 초록을 고치지 않고 그대로 옮깁니다.

   ```markdown
   > [!abstract] Zotero 초록
   > (초록 원문)
   ```

2. 그 아래에 **AI 요약 (초록만 보고 작성)** 이라는 이름을 붙이고 2~3줄로 요약합니다. 초록에 없는 내용은 넣지 않습니다.
3. 초록이 없으면 둘 다 쓰지 않고 "Zotero에 초록이 없습니다"라고만 적습니다.

### 하이라이트

- 색별로 묶습니다. 초록, 노랑, 빨강을 먼저 쓰고, 나머지 색은 나온 순서대로 씁니다. 묶음 안에서는 쪽 순서대로 씁니다.
- 묶음 제목은 `### 초록 — <의미>`처럼 씁니다. 의미가 없으면 `### 초록`만 씁니다.
- 하이라이트 하나는 아래처럼 씁니다. 문장은 한 글자도 고치지 않습니다.

  ```markdown
  > 하이라이트한 문장 그대로
  > — p. 5 · [Zotero에서 열기](zotero://open-pdf/library/items/<attachment_key>?page=<page_index+1>&annotation=<annotation_key>) · 코멘트 C1
  ```

- 쪽 표시 `p.`에는 `page` 값을 씁니다. 링크의 `page`에는 `page_index`에 1을 더한 값을 씁니다.
- 코멘트가 달린 하이라이트는 끝에 `코멘트 C1`처럼 번호를 붙입니다.
- 그림 영역 표시(image)처럼 문장이 없는 주석은 "(그림 영역 표시)"라고 적고 링크를 답니다.
- PDF가 여러 개 붙어 있으면 묶음 안에 첨부 이름을 함께 적습니다.

### 내 코멘트

- 하이라이트에 단 코멘트를 번호 순서대로 모읍니다. 코멘트는 고치지 않습니다.

  ```markdown
  - **C1** (p. 5) 코멘트 그대로
    - 대상: "하이라이트 문장 앞 40자 안팎…"
  ```

- 하이라이트 없이 단 메모 주석(note)도 여기에 넣습니다.
- Zotero 노트가 있으면 `#### Zotero 노트` 아래에 마크다운으로 옮깁니다.
- 아무것도 없으면 "Zotero에 코멘트가 없습니다"라고 적습니다.

### 내 생각

비워 둡니다. 템플릿에 안내 문구가 있으면 그대로 둡니다.

## 7. 저장

1. 논문 노트 폴더(`CLAUDE.md`에 적힌 곳, 없으면 `Literature/`)에 `@인용키.md`로 저장합니다. 폴더가 없으면 만듭니다.
2. **같은 이름의 노트가 이미 있으면 덮어쓰지 않습니다.** 무엇이 달라지는지 짧게 보여 주고 고르게 합니다.
   - 하이라이트와 내 코멘트만 새로 고치기 (비어 있던 속성 값은 채우고, 요약, 내 생각, 사용자가 직접 쓴 부분은 그대로 둡니다)
   - 다른 이름으로 저장하기 (`@인용키 (2).md`)
   - 그만두기

## 8. 보고

짧게 알려 줍니다.

- 저장한 경로
- 하이라이트 수 (색별), 코멘트 수, Zotero 노트 수
- 비어 있는 속성 (예: `doi`, `journal`)
- 쓴 템플릿 (내 템플릿인지 기본 템플릿인지)
- "내 생각"은 직접 쓰시라는 안내

다음 단계로 이 노트를 위키에 반영하는 일(ingest)을 제안할 수 있습니다. 실행은 사용자가 정합니다.
