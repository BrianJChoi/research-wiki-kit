# 연구 검색

## 공용 경로

먼저 이 스킬 파일에서 상대 경로 `../../references/vault-layout.md`를 읽고, 대상 볼트의 `CLAUDE.md`와 함께 적용합니다. 아래 경로 예시는 공용 표의 역할을 뜻하며 사용자 규칙이 우선합니다.

주제 하나를 받아 계획→검색→원문 확인→리포트 저장까지 진행합니다. 기본은 Light 조사이며 서브에이전트를 띄우지 않습니다. 체계적 문헌고찰이나 PRISMA 전체 절차라고 부르지 않습니다.

## 계획

사용자가 준 주제·언어·저장 위치를 따릅니다. 기본은 한국어, 원문 3편, 경로당 후보 5개입니다. 영어·한국어 검색어와 쟁점 질문 3개를 짧게 보여 주고 진행합니다. 자세한 조사를 요청한 경우에만 원문 6편까지 늘립니다.
먼저 내 볼트의 INDEX와 관련 논문·토픽 노트를 훑어 알고 있는 내용과 빠진 근거를 확인합니다. 공용 규칙의 연구 폴더에 `YYYY-MM-DD 주제.md`를 저장하며, 기존 파일이 있으면 보강하거나 새 이름을 정합니다.

## 기본 검색 순서

`references/academic-apis.md`를 필요한 단계에서 읽습니다. 아래 순서를 지킵니다.

1. **Consensus 커넥터:** 연결된 도구를 먼저 확인합니다. 수강생은 Consensus에 가입하고 Claude 커넥터로 연결해 사용합니다. 도구가 실제로 보일 때만 호출하며 없는 도구 이름을 지어내지 않습니다. Windows Code 탭에서 보이는지와 무료 계정 검색 한도는 미확인입니다. 도구가 없거나 한도를 만나면 건너뛰고 표시합니다. 추가 MCP 설치나 유료 구독을 요구하지 않습니다. 기관 계정의 한도를 무료 계정 한도로 안내하지 않습니다.
2. **arXiv:** 영어 키워드로 5편 이하를 찾습니다. 프리프린트와 출판 논문을 구분하고 호출 간 3초 이상 기다립니다. 사회과학 주제에서 결과가 적으면 억지로 채우지 않습니다.
3. **Crossref:** 키 없는 REST API로 DOI·저자·연도·학술지명과 `is-referenced-by-count`를 확인합니다. 사용자가 자신의 연락용 이메일을 제공했거나 개인 환경 변수에 설정했다면 `mailto` polite pool을 사용합니다. 이메일이 없으면 public pool로 진행합니다. 강사 이메일이나 가짜 이메일을 넣지 않습니다.
4. **Zotero:** 읽기만 합니다. 의미 검색 색인이 있으면 사용하고, 없으면 한국어·영어 `zotero_search_items`로 찾습니다. 후보의 메타데이터·초록, 가장 관련 있는 1~2편의 하이라이트·코멘트를 읽습니다. MCP가 없으면 건너뛰고 표시합니다. 새 항목 등록·주석·태그 수정은 하지 않습니다.
5. **웹:** 질문형 검색으로 공식·학술 원문과 반대 근거를 찾고 선택한 페이지를 실제로 엽니다. 검색 결과 문구만 읽었다면 원문 확인으로 세지 않습니다.

**선택 경로:** 본인의 개인 키가 이미 설정돼 있고, 사용자가 추가 경로를 요청하거나 기본 결과가 부족할 때만 OpenAlex·Semantic Scholar를 사용합니다. 키가 없으면 요청을 받았더라도 두 API를 호출하지 않습니다. Semantic Scholar 429는 바로 건너뜁니다. OpenAlex의 키 없는 공용 IP 한도를 기본 경로로 소비하지 않습니다. 강사 설정 파일·키를 읽거나 공유하지 않습니다.

## 원문과 검증

- DOI를 우선하고 정규화한 제목으로 중복을 합칩니다. 인용수는 데이터베이스 이름과 확인 날짜를 남깁니다. Crossref 인용수가 전체 인용수를 대표한다고 말하지 않습니다.
- 리뷰·최근 논문·반대 근거를 섞습니다. 초록·서지 결과와 원문을 구분합니다. Zotero 전문은 필요한 1~2편만 읽습니다.
- 각 출처에 `[원문 확인]`, `[초록만]`, `[서지만]` 중 하나를 붙입니다. 초록만 읽은 사실 주장은 본문에도 `(초록 기준)`을 표시합니다. 서지만 본 항목은 더 읽을 후보로 남깁니다.
- API 오류는 성공으로 간주하지 않습니다. 429에서 정해진 Retry-After가 길면 대기하며 사용량을 쓰지 말고 경로를 건너뜁니다. 선택 DB 외 기본 API의 일시 오류도 한 번만 재시도합니다.
- 외부 웹 원문을 볼트에 통째로 복제할 때는 사용자 요청과 이용 조건을 확인합니다. 리포트에는 필요한 인용·요약·URL만 남깁니다.

## 리포트

YAML은 title, created, type: research-report, tags와 실제 사용 경로를 기록합니다. 본문에는 요약, 질문·검색어, 문헌 종합, 쟁점과 연구 갭 후보, 내 서재·볼트 연결, 커버리지 한계, 참고문헌을 넣습니다.
사실 주장마다 `[1]` 같은 번호를 달고 마지막 참고문헌에 저자·제목·연도·DOI/URL·검색원·검증 표시를 연결합니다. 실제로 열어 본 출처만 인용합니다. 없는 DOI·논문·citekey를 만들지 않습니다.
기존 논문 노트가 있으면 `[[볼트 기준 경로/@citekey]]`로 잇고, 없으면 실제 Zotero select URI를 씁니다. 출처 간 모순은 둘 다 인용합니다. AI 해석은 `해석:`으로 표시합니다.
사용 불가 경로, 개인 키가 없어 건너뛴 DB, 읽지 못한 원문과 근거 수를 보고합니다. 경로가 일부 없어도 확인한 자료로 저장하되 완전한 조사로 말하지 않습니다. 다음 단계는 paper-note 또는 storm-perspectives를 제안하며 연구 질문 선택은 사용자에게 맡깁니다.
