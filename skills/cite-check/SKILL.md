# 인용 검증

## 공용 경로

먼저 이 스킬 파일에서 상대 경로 `../../references/vault-layout.md`를 읽고, 대상 볼트의 `CLAUDE.md`와 함께 적용합니다. 아래 경로 예시는 공용 표의 역할을 뜻하며 사용자 규칙이 우선합니다.

강사의 인용 검증 워크플로를 연구 볼트용으로 고쳤습니다. Zotero는 읽기만 합니다.

1. 대상 원고를 읽습니다. 파일이 없으면 연구 폴더의 후보를 보여 주며 하나를 확정합니다. Zotero 연결이 없으면 접속 제한을 보고하고 실제 근거 확인이 끝났다고 말하지 않습니다.
2. 통계·수치, 이론·선행연구, 일반화에 C1, C2… 번호를 붙입니다. 기존 `[@key]`, `[[@key]]`, `[[Literature/@key|별칭]]`, TODO도 모두 검증 대상입니다.
3. 기존 키는 `zotero_search_by_citation_key`로, 키 없는 주장은 의미 검색으로 찾습니다. 의미 색인이 없으면 `zotero_search_items`의 한국어·영어 검색 2회로 대신합니다. 도구 이름과 인자는 연결된 MCP 스키마를 따릅니다.
4. 후보의 메타데이터·초록·하이라이트를 읽고, 지지가 불명확하면 전문 또는 사용자가 제공한 원문을 확인합니다. 제목만 비슷한 항목을 근거로 쓰지 않습니다. 초록만 확인한 경우 그 범위를 표시합니다.

| 판정 | 원고 처리 |
|---|---|
| 지지 확인 | 메타데이터/BibTeX에서 확인한 `[@citekey]`를 삽입합니다 |
| 애매함 | `⚠️ TODO cite: 근거 지지 확인 필요`와 후보를 보여 줍니다. 자동 인용하지 않습니다 |
| 근거 없음 | `⚠️ TODO cite: 근거 없음`을 남깁니다 |
| 키 없음 | 기존 키는 보존하고 `⚠️ TODO cite: 없는 키 — key`를 옆에 표시합니다 |

5. 원고의 주장 문장은 바꾸거나 삭제하지 않습니다. 인용·검증 표시만 추가하며 같은 표시를 중복하지 않습니다. 근거가 반박하는 주장은 일치 판정하지 말고 불일치로 보고합니다.
6. 키가 `references.bib`에 있는지 대조합니다. 자동 내보내기 파일은 손으로 고치지 않습니다. 없는 항목은 Better BibTeX 갱신을 안내하고, 필요하면 별도 bib에 확인된 서지만 저장합니다. Zotero 서재에는 쓰지 않습니다.
7. 원고를 다시 읽어 키와 표시를 검증합니다. `ID | 주장 | 판정 | 키·쪽·근거 링크 | 원문/초록 확인 범위` 표, 삽입 수·없는 키·미근거 수를 보고합니다. 확인 불가능한 항목을 통과로 세지 않습니다. 없는 근거는 research-search로 찾도록 제안합니다.
